毎朝6時、スマホに「今日のAIニュース」が届きます。記事を選んだのも、日本語に要約したのも、音声で読み上げたのも、メールを送ったのも、すべてプログラムです。人間は一切関与していません。

この記事では、その仕組みをどう作ったか、そして**89日間動かし続けて実際にいくらかかったか**を、包み隠さず公開します。

## 結論：運用89日、API料金は合計103円

先に結果からお見せします。

| 項目 | 実績 |
|---|---|
| 稼働日数 | 89日（ダイジェスト89号） |
| 生成したポッドキャスト | 147エピソード |
| Claude API 料金 | 68円 |
| 音声合成（Google TTS）料金 | 35円 |
| サーバー代 | 0円（GitHub Pages） |
| 実行環境の費用 | 0円（GitHub Actions 無料枠） |
| **合計** | **103円** |

「AIで自動化」と聞くと月数千円かかりそうに思えますが、**やり方を選べば100円程度で回ります**。ポイントは3つです。

1. 要約に使うモデルを軽量なものにする（Claude Haiku を使用）
2. 音声合成を無料のものに切り替える（`edge-tts` を使用。Google TTSは最初の8本のみ）
3. 実行環境とホスティングを無料枠で完結させる（GitHub Actions + GitHub Pages）

## 全体の流れ

処理は毎朝1本のスクリプトが順番に実行しています。

```
① RSS/APIからニュースを収集
      ↓
② キーワードで5カテゴリに分類
      ↓
③ Claude Haiku で日本語タイトル＋要約を生成
      ↓
④ HTMLダイジェストを組み立てて保存
      ↓
⑤ 台本を書いて音声合成 → ポッドキャストMP3
      ↓
⑥ GitHubにpush（＝サイトが自動更新）
      ↓
⑦ メールで配信
```

これを GitHub Actions の `schedule` で毎日叩いているだけです。パソコンの電源は関係ありません。GitHubのサーバーが勝手に動いてくれます。

### なぜ「自分のパソコン」で動かさないのか

自動化でつまずきやすいのが、ここです。自分のPCで `cron` を組むと、**PCを閉じている間は動きません**。旅行に行けば止まります。

GitHub Actions ならクラウド側で実行されるので、こちらは何もしなくていい。しかもパブリックリポジトリなら実行時間は無料です。

```yaml
on:
  schedule:
    # UTC 21:00 = 日本時間の翌朝6:00
    - cron: '0 21 * * *'
  workflow_dispatch:   # 手動実行もできるようにしておく
```

ひとつ落とし穴があります。GitHub Actions は **UTC（協定世界時）で動く**ため、Pythonの中で普通に「今日の日付」を取ると日本時間とズレて前日扱いになります。日本時間基準で日付を確定させる処理を必ず入れてください。

```python
JST = timezone(timedelta(hours=9))
target_date = datetime.now(JST).replace(tzinfo=None)
```

## ① ニュースをどこから集めるか

有料のニュースAPIは使っていません。**無料のRSSフィードだけ**で十分な量が集まります。実際に使っているソースは次のとおりです。

- TechCrunch AI
- VentureBeat AI
- The Verge AI
- MIT Technology Review
- WIRED AI
- Ars Technica
- Hacker News（Algolia の検索APIで新着を取得）

RSSは `requests` で取ってきて `xml.etree.ElementTree` で解析するだけ。専用ライブラリも不要です。日付の書式がソースごとにバラバラなので、そこだけ複数フォーマットを試す処理を書いておくと安定します。

## ② 分類と要約 ─ ここだけAIに任せる

集まった記事を、モデル / 研究 / ビジネス / ポリシー / ツール の5カテゴリに分けています。

重要なのは、**全部をAIにやらせないこと**です。分類はまずキーワードマッチで機械的に振り分け、AIには「日本語タイトルと要約の生成」だけを任せています。これでAPI呼び出し回数が激減し、コストが2桁変わります。

実際の使用量は、記録が残っている範囲で以下のとおりでした。

| 用途 | 呼び出し回数 | 入力トークン | 出力トークン |
|---|---|---|---|
| ニュースの分類・日本語化 | 215回 | 69,362 | 57,512 |
| ポッドキャスト台本の生成 | 8回 | 56,959 | 30,525 |

## ③ ポッドキャスト化 ─ 音声合成は無料でいい

最初の8エピソードは Google Cloud Text-to-Speech（Neural2）を使い、35円かかりました。その後 **`edge-tts` に切り替えて以降の課金はゼロ**です。

```bash
pip install edge-tts
```

日本語音声の品質は、ニュースの読み上げ用途なら十分実用レベルです。2人の話者を交互に喋らせる「対話形式」にすると、単調な読み上げよりぐっと聴きやすくなります。

音声ファイルを結合するのに `ffmpeg` が必要ですが、GitHub Actions のランナーでは `apt` が不安定なことがあります。**取得方法を複数用意してフォールバックさせておく**と、朝のジョブが謎に落ちる事故を防げます。

## ④ 配信 ─ サイト・RSS・メールの3経路

生成物は3つの経路で届けています。

- **サイト**：GitHub Pagesで公開。pushした瞬間に更新される
- **ポッドキャスト**：RSSフィードを自分で生成すれば、Spotifyなどに登録できる
- **メール**：Gmail経由で毎朝送信

ここでハマったのが**順番**です。メールにサイトのリンクを載せるので、pushより先にメールを送ると「まだページが無い」状態でリンクを踏まれます。push → GitHub Pagesのデプロイ完了を待つ → メール送信、の順に固定しました。

## これから作る人へ

同じものを作るのに必要なのは、次の3つだけです。

1. **Python の基礎**（`requests` でAPIを叩けて、ファイルを読み書きできればOK）
2. **GitHub Actions の書き方**（YAMLを20行ほど。テンプレを写経すれば動きます）
3. **AI APIの叩き方**（HTTPリクエストが書ければ同じです）

正直なところ、いちばん難しいのはコードではなく「**毎日確実に動き続ける状態を保つこと**」でした。RSSが落ちる、APIの仕様が変わる、ランナーの環境が変わる。エラーが出ても止まらない作りにしておくのが、結局いちばん重要です。

ゼロから独学でここまで持っていくのがしんどい場合は、体系立てて学べる講座を一度通しでやってしまうほうが早いこともあります。特に「Pythonは書けるがクラウド実行やAPI連携で毎回詰まる」という段階の人は、独学の遠回りが一番コスト高になりがちです。
