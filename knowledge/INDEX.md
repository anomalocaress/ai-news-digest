## このプロジェクトに効くもの

- **ナレッジが続かないのは意志ではなく「設計」の問題** — テツメモさんが1年放置した自分のObsidian保管庫と、よく設計された保管庫を並べて比べたところ、続かなかった原因は根性ではなく構造だった。情報を入れるたびに「これはどこに入れる？」という判断が発生する設計だと、その摩擦が毎回積み上がって手が止まる。唯一続いていたのは、プラグインが自動で取り込むKindleハイライトだけだった。
  <small>テツメモ 06/10・意見・体験・`20260826-33a3d0`</small>
  → 応用: ナレッジ機能は分類を人間に選ばせない（Claudeに話す or Gmailから自動取り込みの2経路だけ） / 取り込んだメールは生のまま置かず、必ず要点に変換してから保存する（inboxは蒸留後に削除）
- **新しいAIを追うより、AIに渡す「自分の情報」を持つほうが効く** — モデルが出るたびに使い方を覚え直すのは消耗するだけで、差がつくのは「自分が何者で、何をしていて、どういう文体で、過去に何を作ったか」をAIに渡せる形で持っているかどうか。AIを「優秀だが自分のことを何も知らない新人」と捉えると、必要なのはプロンプト技術ではなく引き継ぎ資料だと分かる。
  <small>テツメモ 06/10・出典の主張・`20260826-db3c9e`</small>
  → 応用: CLAUDE.md と knowledge/INDEX.md が、このプロジェクトにおける「引き継ぎ資料」そのもの / 毎朝の自動実行に取り込みを載せて、蓄積が人の意志に依存しないようにする
- **Codexの「リモート」でスマホから自宅PCの作業を続けられる** — ChatGPTデスクトップ版のCodexで設定→リモート→QRコードをスマホで読み取るだけで、外出先から進捗確認・追加指示・実行前の承認ができる。ファイルや認証情報はPC側に残り、スマホは操作端末として振る舞う。ただし接続先PCが起動しネットにつながりアプリが動いていることが条件で、スリープすると切れる。
  <small>テツメモ 08/05・検証済み・`20260826-5f45a0`</small>
  → 応用: 毎朝6時の自動生成が転けたとき、外出先から原因確認と再実行ができる備えになる
- **AIの報告は「完了・進行中・要確認」の3つに畳ませる** — AIに任せる作業が増えるほど、長いMarkdownの報告を読むこと自体が負担になる。状態を3項目だけに要約させ、自分の判断が要るものだけ最後に質問としてまとめさせると、スマホでも数十秒で状況を把握できる。さらに報告をHTML化してボタンで「やっていい／相談したい／やらない」を選べるようにすると判断が速くなる。
  <small>テツメモ 08/05・出典の主張・`20260826-f1a0b9`</small>
  → 応用: 毎朝の生成ログと、ナレッジ報告の出力形式をこの3分類に寄せる
- **広告1,000万円をやめて、既存コミュニティへの還元に回した判断** — イケハヤさんがゲームの広告予算1,000万円をスマホ広告に使うのをやめた。アクティブユーザーの獲得単価が1人3,000〜5,000円で、最悪1,000万円かけて500人しか増えない計算になったため。代わりに同額規模を既存コミュニティ向けの施策（トークンのバイバックと還元）に充てた。
  <small>イケハヤ 08/20・出典の主張・`20260826-47f090`</small>
  → 応用: このサイトも広告費ゼロが前提。伸ばすなら既存のメール読者・ポッドキャスト購読者への還元が先 / 月6,700PVという目標も、獲得単価の発想で「何人に何回届けるか」に置き換えて考えられる
